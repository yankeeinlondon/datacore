# Datacore fixtures

The parity vault and the driver that checks Datacore's views render the same before and after a change (Engine Room
spec §9.2; P2 plan step 1).

| Path | What |
|---|---|
| `vault/Parity/*.md` | One note per view/hook area: tables, lists, layout, literals, links/embeds, controls, hooks, queries, `dc.require`, languages, errors |
| `vault/Parity/Data/` | 40 books + 5 authors, generated by `generate.ts` (committed; rerun after changing the generator) |
| `vault/Parity/scripts/` | Script files for `dc.require` |
| `parity-plugin/` | **Datacore Parity Helper** (dev only): renders a note off-screen with `MarkdownRenderer` and returns its HTML |
| `parity.ts` | Driver: `sync`, `snapshot <name>`, `compare <a> <b>` |
| `parity/baseline/` | Committed reference snapshot |

## Running

Needs a running Obsidian with the target vault open (default `Test Vault`; `--vault <name>` or `$PARITY_VAULT`),
`obsidian-cli` registered, and the plugins under test installed and enabled.

```sh
cd fixtures
node parity.ts sync                  # copy vault/ into the target vault; (re)load the helper plugin
node parity.ts snapshot after        # render every Parity/*.md note into parity/after/
node parity.ts compare baseline after
```

`sync` writes only changed files, trashes stale files under `Parity/`, and enables the helper for the session only
(not saved to the vault's plugin list). Nothing outside `Parity/` and `.obsidian/plugins/datacore-parity/` is touched.

**It never takes focus:** everything goes through `obsidian-cli eval`, and notes render into an invisible, off-screen
container, with no leaves, modals, or settings opened and no keystrokes sent. That makes it safe to run while the
machine is in use.

Snapshots are normalized (one tag per line; generated ids and stack-trace frames removed, since frames carry bundle line
numbers). Two snapshots of the same build are identical, including across a full reindex.
